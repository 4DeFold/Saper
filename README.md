# Классический «Сапёр» на Rust

Нативная desktop-игра «Сапёр» в классическом сером оформлении. Игровое
приложение и вся игровая логика написаны на Rust; shell-скрипты используются
только для сборки `.app`/`.dmg` и для CI. Это не Electron, не браузерная игра и
не JavaScript-проект.

Плитки, цифры, флаги, мина, лицо-перезапуск, счётчик, таймер и собственный
стилизованный логотип рисуются кодом; три коротких звуковых эффекта
синтезируются в виде PCM WAV на лету. Для кириллицы в бинарь встроен
DejaVu Sans, лицензия которого лежит отдельно (см. ниже).

## Возможности

- Пресеты «Новичок» (10 мин), «Любитель» (40), «Профессионал» (99) и
  «Своя игра». **Число мин пресета фиксировано** и не меняется при изменении
  ширины/высоты поля, пока значение допустимо.
- Произвольные размеры: ширина 10–200, высота 10–100, мины
  `1 … ширина × высота − 1`, но не больше 19 999. Значения вне диапазона
  автоматически ограничиваются, а не приводят к падению.
- Безопасный первый ход: мины расставляются **после** первого открытия.
  Резервируется область 3×3 вокруг первой клетки, но не больше безопасных
  клеток, чем позволяет плотность мин. При `мины = площадь − 1` безопасна
  ровно одна клетка, первый ход мгновенно выигрывает, rejection-циклов и
  зависаний нет (проверяется тестом на поле 200×100 / 19 999 мин).
- Классические действия: открытие, флаг, «аккорд» (ЛКМ по открытой цифре при
  нужном числе флагов), победа, поражение, показ мин после поражения.
- Счётчик мин (может уходить в отрицательные значения), таймер до 999 с,
  лицо-перезапуск с разными выражениями, цифры разных цветов.
- Звук открытия/флага, поражения и победы; выключается кнопкой «Звук».
- Масштабирование кнопками `−`/`+`/`100%` и `Ctrl`+колёсико; изменение размера
  окна; полноэкранный режим кнопкой или `F11`.
- Навигация по большим полям: колёсико мыши / двухпальцевый жест тачпада
  прокручивает поле, `Shift`+перетаскивание или средняя кнопка — сдвигает,
  стрелки — пошаговый сдвиг. Все интерфейсные элементы центрированы.
- Режим автоматического smoke-запуска: `--smoke 45 --marker /tmp/ok.txt`
  открывает окно, отрисовывает 45 кадров, пишет маркер и завершается.
  Режим `--headless --marker /tmp/ok.txt` запускается **до создания окна**:
  проверяет, что исполняемый файл стартовал из `.app`, что ресурсы бандла на
  месте, и прогоняет игровую логику. Используется в headless CI.

## Требования

- Rust stable + Cargo (проверялось в GitHub Actions на `ubuntu-latest` и
  `macos-15` ARM64).
- Linux: системные библиотеки X11/OpenGL/звука, которые обычно есть на
  desktop-системе; для headless-сервера нужен X-сервер (Xvfb).
- macOS: Apple Silicon (`arm64`), macOS 11+, Xcode Command Line Tools,
  `hdiutil`, `iconutil`, `codesign`, `plutil` (все входят в macOS/Xcode).

## Запуск из исходников

```sh
cargo run --release
```

Для отладочного запуска достаточно `cargo run`. Если на Linux нет графической
сессии, окно не откроется — это ожидаемо, но логика при этом проверяется
тестами без окна.

## Управление

| Действие | Управление |
| --- | --- |
| Открыть клетку | ЛКМ или `E` (по умолчанию) |
| Открыть соседей цифры («аккорд») | ЛКМ по уже открытой цифре при верном числе флагов |
| Поставить / снять флаг | ПКМ, щелчок двумя пальцами на тачпаде или `Q` (по умолчанию) |
| Переназначить `Q`/`E` | «Настройки» → «Клавиши управления» → клик по кнопке → новая клавиша |
| Масштаб | кнопки `−` / `+` / `100%` или `Ctrl`+колёсико |
| Прокрутка большого поля | колёсико / двухпальцевый жест, стрелки, `Shift`+перетаскивание, средняя кнопка |
| Полный экран | кнопка «Полный экран» или `F11` |
| Закрыть настройки | «Готово» или `Esc` |
| Новая игра | клик по лицу в шапке |

`Q` и `E` переназначаются **в игре**, без пересборки; настройки хранятся в
памяти процесса и сбрасываются при перезапуске приложения.

## Уровни и размеры

| Уровень | Мины | Стартовый размер |
| --- | --- | --- |
| Новичок | 10 | 10 × 10 |
| Любитель | 40 | 16 × 16 |
| Профессионал | 99 | 30 × 16 |
| Своя игра | задаётся игроком | текущий размер |

Минимальный размер 10×10 задан требованием к пользовательскому уровню, поэтому
классическое поле 9×9 недоступно. При выборе пресета размер сбрасывается на
стартовый, а число мин остаётся фиксированным; последующее изменение размеров
в настройках мин не меняет. Для «Своей игры» число мин ограничивается
`площадь − 1` и 19 999.

## Проверки и тесты

Основные команды ( workspace из двух крейтов, поэтому используется
`--workspace` / `--all`):

```sh
cargo fmt --all -- --check
cargo check --workspace --all-targets
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo build --release --workspace
```

Тот же набор выполняет `./scripts/ci-checks.sh`, а GitHub Actions публикует
его полный вывод в комментарии к коммиту.

Логика вынесена в отдельный крейт `crates/minesweeper-core` **без внешних
зависимостей**, поэтому тесты запускаются без окна и без графических библиотек.
Покрыто:

- ограничения ширины 10–200, высоты 10–100, мин `1 … площадь − 1`,
  максимум 19 999, а также корректное ограничение невалидных значений;
- фиксированное число мин у пресетов при смене размера поля (10/40/99);
- безопасный первый ход для 32 сидов и разных позиций;
- отсутствие зависания и мгновенная победа при максимальной плотности
  (10×10/99, 10×100/999, 50×50/2499, 200×100/19 999);
- победа при открытии всех безопасных клеток, поражение при открытии мины;
- установка и снятие флага, запрет флага на открытой клетке, счётчик мин;
- открытие пустой области и корректность всех цифр соседства;
- «аккорд» при верных флагах;
- полный сброс состояния после перезапуска.

Дополнительно в `src/main.rs` есть тесты геометрии интерфейса: центрирование
панели и поля в окнах 360×240 … 1920×1080, а также bounded viewport и
необходимость прокрутки для поля 200×100.

## Сборка `.app` и DMG для Apple Silicon

Запускать нужно на Mac с Apple Silicon: `hdiutil`, `iconutil` и `codesign` —
системные утилиты macOS, на Linux DMG не собрать.

```sh
rustup target add aarch64-apple-darwin
./build-dmg.sh
```

Скрипт `build-dmg.sh`:

1. Проверяет `uname -s = Darwin`, `uname -m = arm64` и host `rustc`, равный
   `aarch64-apple-darwin`. На Intel-машине сборка **прерывается**: артефакт не
   называется Apple Silicon без подтверждённой архитектуры.
2. Собирает `cargo build --release --target aarch64-apple-darwin`.
3. Собирает `build/Classic Minesweeper.app` вручную: `Contents/MacOS`,
   `Contents/Info.plist`, `Contents/Resources` (шрифт, лицензия шрифта,
   `LICENSE`, `README.md`, иконка `.icns` из `assets/icon.png`).
   Сторонний `cargo-bundle` не нужен.
4. Подписывает `.app` **ad-hoc** (`codesign -s -`): на Apple Silicon это
   необходимо даже для локального запуска. Это не Developer ID и не
   notarization.
5. Проверяет `plutil -lint`, `lipo -archs` (должно быть `arm64`) и структуру
   `.app`.
6. Кладёт `.app` и символьную ссылку на `/Applications` в staging-папку и
   создаёт `dist/Classic-Minesweeper-Apple-Silicon.dmg` через `hdiutil`,
   затем проверяет его `hdiutil verify` и печатает SHA-256.

Целевой файл: **`dist/Classic-Minesweeper-Apple-Silicon.dmg`**.

Проверка запуска именно как macOS-приложения (используется в CI):

```sh
# Запуск через LaunchServices именно .app, без OpenGL:
open -n -a "$PWD/build/Classic Minesweeper.app" --args --headless --marker /tmp/ok.txt
# /tmp/ok.txt содержит "HEADLESS OK", пути к ресурсам и результаты проверок логики

# На реальном Mac с GUI: окно, отрисовка кадров, маркер
open -n -a "$PWD/build/Classic Minesweeper.app" --args --smoke 45 --marker /tmp/gui.txt
# /tmp/gui.txt содержит "SMOKE OK: frames=45"
```

## GitHub Actions

`.github/workflows/ci.yml`:

- **checks** (`ubuntu-latest`): `rustfmt`, `cargo check`, `cargo test`,
  `cargo clippy -- -D warnings`, release-сборка, а также запуск собранного
  бинаря под Xvfb с software OpenGL (`--smoke 30`) — подтверждена реальная
  отрисовка кадров. Полный лог публикуется комментарием к коммиту и
  артефактом `ci-checks-report`.
- **macos-arm** (`macos-15`, подтверждённый ARM64-раннер): проверка
  `uname -m = arm64`, тесты логики, `./build-dmg.sh`, проверка `lipo -archs`,
  запуск `.app` через `open -a --headless` (проверка бандла, ресурсов и логики),
  `hdiutil verify`, SHA-256. Дополнительно, информативно, делается попытка
  `--smoke` с настоящим окном. DMG выкладывается артефактом
  `Classic-Minesweeper-Apple-Silicon`.
- При пуше тега `v*` тот же job создаёт GitHub Release и прикладывает DMG.

Ссылки на конкретный запуск и артефакт приводятся в описании Pull Request и в
финальном отчёте. Артефакты Actions доступны для скачивания в разделе
**Actions → нужный запуск → Artifacts**.

## Подпись и notarization

Скрипт делает только **ad-hoc подпись** (`codesign -s -`). Этого достаточно для
запуска на своём Mac (при первом запуске, возможно, понадобится «Открыть» через
контекстное меню / снять карантин `xattr -d com.apple.quarantine`). Для
распространения за пределы локального использования нужны:

- сертификат **Developer ID Application** и подпись им;
- `notarytool` с учётными данными Apple (Apple ID / App Store Connect API key);
- затем `xcrun stapler` и hardened runtime для готового релиза.

Ни сертификаты, ни учётные данные, ни токены в репозиторий не кладутся и в CI
не используются. Если вы захотите подписать релиз, добавьте секреты в
настройках репозитория самостоятельно и расширьте workflow — здесь это
намеренно не имитируется.

## Ограничения

- Минимальное поле 10×10; классические 9×9 и «первый клик всегда нулевой на
  9×9» недоступны по условию задачи.
- Таймер ограничен 999 секундами, как в классической игре; время между
  сессиями не сохраняется, рекордов и таблицы лидеров нет.
- Настройки (размеры, клавиши, звук, полноэкранный режим) не сохраняются на
  диск и сбрасываются при перезапуске.
- Только `aarch64-apple-darwin`. Intel-сборка, universal binary и Windows/Linux
  инсталляторы не собираются; приложение, впрочем, собирается и запускается на
  Linux из исходников.
- Окно меньше ~360×320 пикселей тесновато: элементы остаются центрированными,
  но часть подписей может накладываться. Рекомендуется 800×600 и больше.
- GUI не покрыто пиксельными/автоматизированными UI-тестами. Реальная
  отрисовка кадров проверена под Xvfb на Linux (software OpenGL, 30 кадров);
  на hosted **macOS**-раннере OpenGL-контекст отсутствует: miniquad падает на
  создании GL pixel format, поэтому окно `.app` в CI не отрисовывается.
  Вместо этого обязательно проверяется запуск именно `.app` через
  LaunchServices (`open -a --headless`), структура и ресурсы бандла,
  архитектура `arm64` и вся игровая логика; попытка macOS GUI smoke логируется
  информативно и не ломает сборку. Ручную проверку управления и звука нужно
  делать на реальном Mac с GUI.
- На машинах без звукового устройства ALSA-поток `quad-snd` может вывести
  `Can't open PCM device` и завершиться panic-ом в фоновом потоке; основной
  поток и игра продолжают работать (проверено под Xvfb: 30 кадров, exit 0).
- Звуковые эффекты — простые синтезированные сигналы, а не семплы из
  оригинальной игры.
